
## 2026-02-11 - Godot 4.x visual/runtime research decisions

- Keep current `TileMap` node contract in this branch for compatibility (`GroundLayer`, `SoilLayer`, `CropLayer` in `scenes/farm/farm_world.tscn`) while planning a separate migration step to `TileMapLayer`; Godot 4.6 marks `TileMap` deprecated, but current tests assert `TileMap` types and node names (sources: https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_tilemap.rst#L16-L33, https://docs.godotengine.org/en/4.6/classes/class_tilemap.html, `test/integration/test_main_bootstrap.gd:52`).
- For denser composition, prefer multiple render layers with strict responsibility split (gameplay layers vs decorative layers) and maintain reorder-safe layer naming; this aligns with TileMapLayer guidance and minimizes save/gameplay coupling (sources: https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/tutorials/2d/using_tilemaps.rst#L42-L104, https://docs.godotengine.org/en/4.6/tutorials/2d/using_tilemaps.html).
- Continue camera-limit recalculation on viewport resize and base assertions on real screen center/zoom behavior rather than raw node position; `Viewport.size_changed` is the correct trigger, and Camera2D limits/smoothing/offset interactions must be respected (sources: https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_viewport.rst#L276-L283, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_camera2d.rst#L28-L28, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_camera2d.rst#L487-L583).
- Preserve width-fill objective by keeping `project.godot` stretch strategy aligned with `canvas_items + expand`; this is the official non-pixel-art recommendation and best fit for fill-width behavior across aspect ratios (sources: https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/tutorials/rendering/multiple_resolutions.rst#L157-L244, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/tutorials/rendering/multiple_resolutions.rst#L371-L390, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_projectsettings.rst#L4993-L5005).
- For pixel-art quality guardrails, default to Lossless import for 2D sprites, avoid VRAM-compressed modes for low-res pixel art, and only use integer scale mode when strict pixel-perfect output is worth possible black bars/clipping tradeoffs (sources: https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/tutorials/assets_pipeline/importing_images.rst#L158-L185, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/classes/class_projectsettings.rst#L5023-L5035, https://github.com/godotengine/godot-docs/blob/bf0ea4d3d4935249c7e30078ff0445f7f030ac20/tutorials/rendering/multiple_resolutions.rst#L301-L337).
